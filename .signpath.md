# Plan: Code Signing with SignPath Foundation

## Context
The DivePlay installer is not code-signed, so Windows SmartScreen shows an "unknown publisher" warning on every install. The goal is to sign the `.exe` produced by NSIS so SmartScreen recognises the installer as safe.

DivePlay is GPL-2.0 open source, so it is eligible for the **SignPath Foundation** — a free code-signing service for OSS, operated by SignPath GmbH.

---

## Phase 1 — Manual process (outside the code)

These steps must be completed before any change to the repository:

1. **Download the OSS form:**  
   `https://signpath.org/assets/OSSRequestForm-v4.xlsx`

2. **Fill it in and email it to `[email protected]`:**
   - Project name: DivePlay
   - Repository URL: `https://github.com/dougmb/diveplay`
   - License: GPL-2.0
   - Contact: dougmbs@gmail.com

3. **Wait for approval** (~1–2 weeks). You will receive:
   - Organization ID
   - SignPath.io access credentials

4. **In SignPath.io after approval:**
   - Create the `diveplay` project
   - Create the `release-signing` signing policy
   - Under *Trusted Build Systems*, connect the GitHub repository
   - Generate an API token with submitter permission

5. **Add the secrets on GitHub** (Settings → Secrets → Actions):
   - `SIGNPATH_API_TOKEN` — the token generated in the previous step
   - `SIGNPATH_ORGANIZATION_ID` — the organization ID in SignPath
   - `SIGNPATH_PROJECT_SLUG` — `diveplay`
   - `SIGNPATH_SIGNING_POLICY_SLUG` — `release-signing`

## Phase 2 — Code change

### Modified file: `.github/workflows/release.yml`

**Strategy:** split the build from the release. `tauri-action` is used only to compile (without creating the release). The unsigned installer is uploaded as a GitHub Actions artifact → SignPath picks it up, signs it and returns it → the release is created with the signed `.exe` + `diveplay-web.html`.

**Additional permissions required:**
- `id-token: write` — so SignPath can validate that the build came from GitHub Actions (OIDC)

**New workflow flow:**

```
1. checkout + setup node + rust + npm install  (same as today)
2. tauri-action WITHOUT tagName/releaseName     (compile only)
3. upload-artifact of the unsigned .exe         (required by SignPath)
4. signpath/github-action-submit-signing-request (signs and downloads to ./signed/)
5. Copy-Item dist\index.html → diveplay-web.html
6. softprops/action-gh-release with both files: signed/*.exe + web.html
```

### Expected `release.yml` diff:

**Add** to `permissions`:
```yaml
id-token: write
```

**Replace** the `Build and Release Desktop App` step with:
```yaml
- name: Build Desktop App
  uses: tauri-apps/tauri-action@v0
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  # no tagName = does not create a release
```

**Add** after the build:
```yaml
- name: Upload Unsigned Installer
  id: upload-unsigned
  uses: actions/upload-artifact@v4
  with:
    name: unsigned-installer
    path: src-tauri/target/release/bundle/nsis/*.exe

- name: Sign with SignPath Foundation
  uses: signpath/github-action-submit-signing-request@v2
  with:
    api-token: ${{ secrets.SIGNPATH_API_TOKEN }}
    organization-id: ${{ secrets.SIGNPATH_ORGANIZATION_ID }}
    project-slug: ${{ secrets.SIGNPATH_PROJECT_SLUG }}
    signing-policy-slug: ${{ secrets.SIGNPATH_SIGNING_POLICY_SLUG }}
    github-artifact-id: ${{ steps.upload-unsigned.outputs.artifact-id }}
    wait-for-completion: true
    output-artifact-directory: ./signed
```

**Replace** the `Prepare Web Version` + `Upload Web HTML` steps with a single release step:
```yaml
- name: Prepare Web Version
  run: Copy-Item -Path dist\index.html -Destination dist\diveplay-web.html
  shell: powershell

- name: Create Release
  uses: softprops/action-gh-release@v1
  with:
    name: DivePlay ${{ github.ref_name }}
    body: 'Download the Desktop App installer or the portable standalone Web player below.'
    files: |
      ./signed/*.exe
      dist/diveplay-web.html
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

5. Install the `.exe` — SmartScreen should not show the unknown-publisher warning
6. Check the file properties → the *Digital Signatures* tab should list the certificate

---

## Note on SmartScreen
Even with an OV (not EV) signature, SmartScreen may still warn on the first few installs until the file builds up reputation. The SignPath Foundation certificate is OV. Eliminating the warning entirely and immediately would require EV — but with OV the warning changes from "unknown publisher" to "verified publisher", and fades over time.
