# Plano: Assinatura de Código com SignPath Foundation

## Context
O instalador do DivePlay não tem assinatura de código, então o Windows SmartScreen exibe um aviso de "publisher desconhecido" a cada instalação. O objetivo é assinar o `.exe` produzido pelo NSIS para que o SmartScreen reconheça o instalador como seguro.

DivePlay é GPL-2.0 open-source, então é elegível para o **SignPath Foundation** — serviço gratuito de code signing para OSS, operado pela SignPath GmbH.

---

## Fase 1 — Processo manual (fora do código)

Esses passos precisam ser feitos antes de qualquer mudança no repositório:

1. **Baixar o formulário OSS:**  
   `https://signpath.org/assets/OSSRequestForm-v4.xlsx`

2. **Preencher e enviar por email para `[email protected]`:**
   - Project name: DivePlay
   - Repository URL: `https://github.com/dougmb/diveplay`
   - License: GPL-2.0
   - Contact: dougmbs@gmail.com

3. **Aguardar aprovação** (~1–2 semanas). Você receberá:
   - Organization ID
   - Credenciais de acesso ao SignPath.io

4. **No SignPath.io após aprovação:**
   - Criar projeto `diveplay`
   - Criar signing policy `release-signing`
   - Em *Trusted Build Systems*, conectar ao repositório GitHub
   - Gerar API Token com permissão de submitter

5. **Adicionar secrets no GitHub** (Settings → Secrets → Actions):
   - `SIGNPATH_API_TOKEN` — token gerado no passo anterior
   - `SIGNPATH_ORGANIZATION_ID` — ID da organização no SignPath
   - `SIGNPATH_PROJECT_SLUG` — `diveplay`
   - `SIGNPATH_SIGNING_POLICY_SLUG` — `release-signing`

## Fase 2 — Mudança no código

### Arquivo modificado: `.github/workflows/release.yml`

**Estratégia:** Separar o build do release. O `tauri-action` será usado só para compilar (sem criar o release). O instalador unsigned é enviado como artifact do GitHub Actions → SignPath o pega, assina e devolve → release criado com o `.exe` assinado + `diveplay-web.html`.

**Permissões adicionais necessárias:**
- `id-token: write` — para SignPath validar que o build veio do GitHub Actions (OIDC)

**Novo fluxo do workflow:**

```
1. checkout + setup node + rust + npm install  (igual ao atual)
2. tauri-action SEM tagName/releaseName         (só compila)
3. upload-artifact do .exe unsigned             (necessário para SignPath)
4. signpath/github-action-submit-signing-request (assina e baixa para ./signed/)
5. Copy-Item dist\index.html → diveplay-web.html
6. softprops/action-gh-release com os dois arquivos: signed/*.exe + web.html
```

### Diff esperado do `release.yml`:

**Adicionar** em `permissions`:
```yaml
id-token: write
```

**Substituir** o step `Build and Release Desktop App` por:
```yaml
- name: Build Desktop App
  uses: tauri-apps/tauri-action@v0
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  # sem tagName = não cria release
```

**Adicionar** após o build:
```yaml
- name: Upload Unsigned Installer
  id: upload-unsigned
  uses: actions/upload-artifact@v4
  with:
    name: unsigned-installer
    path: src-tauri/target/release/bundle/nsis/*.exe

- name: Sign with SignPath Foundation
  uses: signpath/github-action-submit-signing-request@v2
  with:
    api-token: ${{ secrets.SIGNPATH_API_TOKEN }}
    organization-id: ${{ secrets.SIGNPATH_ORGANIZATION_ID }}
    project-slug: ${{ secrets.SIGNPATH_PROJECT_SLUG }}
    signing-policy-slug: ${{ secrets.SIGNPATH_SIGNING_POLICY_SLUG }}
    github-artifact-id: ${{ steps.upload-unsigned.outputs.artifact-id }}
    wait-for-completion: true
    output-artifact-directory: ./signed
```

**Substituir** os steps `Prepare Web Version` + `Upload Web HTML` por um único step de release:
```yaml
- name: Prepare Web Version
  run: Copy-Item -Path dist\index.html -Destination dist\diveplay-web.html
  shell: powershell

- name: Create Release
  uses: softprops/action-gh-release@v1
  with:
    name: DivePlay ${{ github.ref_name }}
    body: 'Download the Desktop App installer or the portable standalone Web player below.'
    files: |
      ./signed/*.exe
      dist/diveplay-web.html
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

## Observação sobre o SmartScreen
Mesmo com assinatura OV (não EV), o SmartScreen pode ainda avisar nas primeiras instalações até o arquivo acumular reputação. O certificado do SignPath Foundation é OV. Para eliminar o aviso 100% imediatamente seria necessário EV — mas com OV o aviso muda de "publisher desconhecido" para "publisher verificado", e desaparece com o tempo.
